通用 AI CLI vs. 場景專用 AI：以 Lovable Web 開發為例的效能實測

講師：林建宏（Wolke Lin）　課程：2026/10/14 13:30–15:00

今天要完成的事

用 Lovable 與自己的通用 AI 工具各建一版議程收藏器，再各修改一次需求。你需要帶走能操作的作品、驗收紀錄，以及適合自己工作情境的工具選擇理由。

全部議程與講者為合成教學資料。兩條路徑使用相同功能、資料與驗收標準。講師使用 Codex 桌面 App，你可以使用已準備好的其他工具。

講師

林建宏（Wolke Lin），Google Developer Expert、LINE Expert 與技術書作者。分享 AI 人機協作、提示工程及程式開發，將教學視為幫助學員理解問題與開始實作的方式。背景及著作可見 Medium。

課前準備（13:00–13:30）

  1. 開啟瀏覽器，登入 Lovable，查看剩餘建置額度。若今天的 5 點已用完，請向講師示意，由講師私下提供群組加入方式。
  2. 確認自己的通用 AI 工具已安裝、登入且能修改本機專案。
  3. 本機實作需 Node.js 24，或相容的 22.12 以上版本。在終端機執行 node --version、npm --version。
  4. 解壓教材，複製 starter 成為自己的實驗目錄，進入該目錄執行 npm ci。
  5. 執行 npm run dev，開啟終端機顯示的網址。看到「環境已就緒」即可。
  6. 準備計時器與 measurement-template.md。先不要看 reference-v1、reference-v2。

首次安裝套件需要網路。macOS 可在終端機輸入 cd 後拖入資料夾；Windows 可在資料夾空白處選「在終端機中開啟」。請以終端機實際顯示的網址為準，通常是 http://localhost:5173。

Lovable 免費方案有每日 5 點與每月 30 點建置上限，任務耗點不固定。若額度已用完或不足，講師會私下提供群組加入方式，加入後確認實作入口與可用狀態。仍無法建置時，再使用離線備援教材。官方來源見本文最後。

第一版完成標準

  1. 顯示議程名稱、講者、主題、會議室、起訖時間，依開始時間排序，同時段依 ID 排序。
  2. 以一個輸入框搜尋名稱或講者。忽略頭尾空白及英文字母大小寫。
  3. 提供主題篩選，與搜尋條件同時生效（AND）。包含「全部主題」。
  4. 每筆資料可加入或取消收藏。重複點擊不得產生重複收藏。
  5. 提供「我的議程」視圖及收藏數量，依開始時間排序。
  6. localStorage 只儲存收藏 ID 陣列，鍵名 hwdc-lab-favorites-v1。同一瀏覽器、同一網址重新整理後保留收藏。
  7. 搜尋無結果及尚無收藏都要顯示可理解的空白狀態。
  8. 繁體中文介面，在桌面及 390px 寬度可操作，時間顯示採 Asia/Taipei。

實作 A：Lovable

  1. 在 Lovable 建立新的空白專案，不使用已有功能的範本。
  2. 開啟 prompt-lovable-v1.txt，完整複製內容。檔案已包含同一份 12 筆資料。
  3. 開始計時並送出建置需求。若工具先產生計畫，確認進入實作後再觀察預覽；所有往返都保留紀錄。
  4. 看到可操作畫面後，依 A1–A6 操作。畫面出現只是開始。
  5. 問題描述要包含實際結果、預期結果與重現方式，使用本文的除錯提示。
  6. 15 分鐘截止時記下完成項目、耗時、追加提示及可見用量。

實作 B：Codex 桌面 App

  1. 使用未修改的 starter 副本。不要將 Lovable 產生的程式帶進來。
  2. 在桌面 App 選擇 Codex，開啟自己的專案資料夾。
  3. 使用 prompt-codex-v1.txt，讓工具讀 requirements-v1.md、acceptance-v1.md 及 src/sessions.json。
  4. 開始計時，讓工具實作並啟動預覽。確認它操作的是本次專案。
  5. 查看檔案修改、終端機輸出與預覽，按 A1–A6 驗收。
  6. 15 分鐘截止時保存結果。其他通用工具可用相同需求，只替換開啟專案及啟動的方法。

計時

初版最多 15 分鐘，包含驗收。截止仍未完成時填寫當下通過項數及失敗項，不把「15 分鐘截止」寫成「15 分鐘完成」。

第二輪：需求變更

講師發布第二輪後，開啟 prompt-revision-v2.txt。先在 Lovable 執行 5 分鐘，再在通用工具執行 5 分鐘。修改前記下目前收藏，修改後確認仍在。

加入收藏議程衝堂提示，保留所有既有功能和收藏資料。

  1. 比較全部收藏議程，不受搜尋、主題篩選或目前視圖影響。
  2. 以時間區間判斷。部分重疊、完全包含及相同時段都算衝堂，首尾相接不算。
  3. 規則為 a.start < b.end && b.start < a.end，時間要先轉換成可比較的時間值。
  4. 清楚顯示衝堂的兩個議程名稱及各自時段。同一對只列一次，不與自己比較。
  5. 不自動取消任何收藏，讓使用者自己決定。
  6. 取消收藏後即時更新提示。
  7. 維持原 localStorage 鍵名與 ID 格式，重新整理仍保留第一版的收藏。

共用需求正文

兩套工具的需求正文一致。Lovable 版另外附上完整 JSON，本機版指定既有檔案。不要刻意替其中一套工具增加功能或預先提供解答。

請建立「研討會議程收藏器」，使用下列合成教學資料，不要更動資料。

功能：顯示全部 12 場的名稱、講者、主題、會議室及台北時間，依開始時間排序。同時段依 ID 排序。可用名稱或講者搜尋，忽略頭尾空白及英文大小寫。可選主題，搜尋與主題條件採 AND。可加入與取消收藏，收藏不得重複。可切換「所有議程」及「我的議程」，顯示收藏數量。沒有結果或收藏時顯示清楚提示。

收藏以 ID 陣列寫入 localStorage，鍵名固定為 hwdc-lab-favorites-v1。同一瀏覽器、同一網址重新整理後保留。若環境有伺服器渲染，請只在瀏覽器端讀寫 localStorage。

介面為繁體中文，白底、深色文字、藍色重點，桌面及 390px 寬度均可使用。標示「合成教學資料，非 HWDC 真實議程」。使用本機資料，不建立登入、資料庫、外部 API、衝堂提示或行事曆匯出，不使用外部圖片。

請實作並啟動可預覽的版本，再實際檢查搜尋、主題篩選、收藏、我的議程、重新整理後保留以及手機寬度。回覆啟動方式、已驗證項目及仍有問題的項目。

紀錄與比較

使用 measurement-template.md。區分設定、建置、修改和除錯。建置經過時間已包含等待及除錯，不要把除錯時間再加一次。

比較時先看完成項目，再看花了多少時間與用量。不同人的模型、網路、經驗與起始狀態不同，課堂觀察不能直接整理成工具排行榜。

訂閱費、額外付費及工具額度分別記錄。用量沒顯示就寫「未取得」。若使用講師提供的群組，註明額度來源與切換時間；群組的總消耗不能直接當成自己的用量。人的主動操作時間與等待時間分開，決定是否計入等待成本時要說明假設。

卡關與備援

狀況 接續方式

備援程式是 Codex 製作的教學解答，不是你的實測成果。使用備援時請在紀錄中註明。

課後練習：行事曆匯出

將收藏議程匯出為 .ics。每場一個 VEVENT，包含穩定 UID、DTSTAMP、開始與結束時間、名稱及會議室。轉成 UTC 後使用 Z 結尾，正確跳脫文字並以 CRLF 分行。測試中文、逗號、分號、換行及沒有收藏的情境。延伸提示與參考實作見 extension-ics.md。
