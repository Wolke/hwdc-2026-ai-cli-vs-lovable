HWDC 2026 學員講義

講師：林建宏（Wolke Lin）｜2026/10/14 13:30–15:00

用 Lovable 與自選通用 AI 工具各做一版「我的 HWDC 議程」。同一份公開議程附件、同樣的 UX 任務，UI 由學員自由設計，但自己的兩個工具版本須保持一致。先用一句話描述想要的 UI，再把相同設計要求交給兩套工具。

90 分鐘聚焦兩套 AI 工具的建置、需求修改與驗收。每套初版 15 分鐘、修改 5 分鐘，驗收包含在時間內；到時保存成果與未完成項目。

講師

林建宏（Wolke Lin），Google Developer Expert、LINE Expert 與技術書作者。分享 AI 人機協作、提示工程及程式開發，將教學視為幫助學員理解問題與開始實作的方式。背景及著作可見 Medium。

課前準備（13:00–13:30）

  1. 開啟瀏覽器，登入 Lovable，查看剩餘建置額度。若今天的 5 點已用完，填寫 群組加入申請表，留下 Lovable 登入 email，再向講師示意。
  2. 確認自己的通用 AI 工具已安裝、登入且能修改本機專案。
  3. 本機實作需 Node.js 24，或相容的 22.12 以上版本。在終端機執行 node --version、npm --version。
  4. 解壓教材，複製 starter 成為自己的實驗目錄，進入該目錄執行 npm ci。
  5. 執行 npm run dev，開啟終端機顯示的網址。看到「環境已就緒」即可。
  6. 準備計時器與 measurement-template.md。先不要看 reference-v1、reference-v2。

首次安裝套件需要網路。macOS 可在終端機輸入 cd 後拖入資料夾；Windows 可在資料夾空白處選「在終端機中開啟」。請以終端機實際顯示的網址為準，通常是 http://localhost:5173。

Lovable 免費方案有每日 5 點與每月 30 點建置上限，任務耗點不固定。若額度已用完或不足，可填寫 群組申請表，由講師安排邀請，加入後確認實作入口與可用狀態。仍無法建置時，再使用離線備援教材。官方來源見本文最後。

給 Agent 的初版提示

先把 hwdc-agenda-2026.json 當附檔上傳，再貼下面這幾句。Codex 的同一份資料已放在 src/sessions.json。

請用附件的 HWDC 議程做一個繁體中文「我的議程」網站：
能搜尋議程或講者、依日期和主題篩選、加入或取消收藏，並查看自己的議程；重新整理後收藏要保留。
搜尋與篩選可以一起用，日期時間要清楚，手機也能操作。資料照附件，保留來源。
不用登入。做好後請開啟預覽，讓我試用。
（UI 由學員自由發揮，但請讓兩個版本保持一致。）

你可以再說一個自己的視覺想法，例如「像我的旅行手帳」或「讓我一眼看懂一天的安排」。記下自己補充的設計要求，分享時討論差異。這些要求影響作品風格，不作工具能力排名的共同條件。

實作 A：Lovable（15 分鐘）

  1. 新建專案，上傳 JSON 附檔，確認附件在訊息中。
  2. 貼短提示、開始計時。預覽能操作後，按 A1–A6 檢查。
  3. 發現缺漏時描述實際操作、預期與結果，追加一次修正並保留紀錄。
  4. 到時保存結果。額度用完者填寫群組申請表並向講師示意；卡關超過 2 分鐘換備援。

實作 B：通用 AI（15 分鐘）

  1. 開啟全新的 starter 副本；不要帶入 Lovable 程式。
  2. 告訴 Agent 資料在 src/sessions.json，使用相同短提示。
  3. 讓 Agent 實作並開預覽，照同一張表驗收。加入與 Lovable 相同的 UI 設計要求，讓兩個版本保持一致。

第二版：收藏議程衝堂提醒

在現有作品增加衝堂提示，保留第一版收藏、設計與既有功能。樣式與提醒位置自由。

比較全部收藏，不受搜尋、日期、主題或視圖影響。部分重疊、完全包含、相同時段都算衝堂；首尾相接不算。以含日期的時間比較：a.start < b.end && b.start < a.end。不能只比 HH:mm。

每對只列一次，不與自己比較；說清楚是哪兩場、哪一天與何時。使用者自己決定，不能自動刪除收藏。取消後立即更新，原有收藏格式不能改到遺失資料。

紀錄與比較

使用 measurement-template.md。區分設定、建置、修改和除錯。建置經過時間已包含等待及除錯，不要把除錯時間再加一次。

比較時先看完成項目，再看花了多少時間與用量。不同人的模型、網路、經驗與起始狀態不同，課堂觀察不能直接整理成工具排行榜。

Lovable 可在每則回覆的 More options → Credits used 查看消耗。Codex 另記模型、速度模式與可取得的用量；若用 token 估算，分開快取與未快取輸入並標明假設。詳細示例見 彩排費用紀錄。

訂閱費、額外付費及工具額度分別記錄。用量沒顯示就寫「未取得」。若使用講師提供的群組，註明額度來源與切換時間；群組的總消耗不能直接當成自己的用量。人的主動操作時間與等待時間分開，決定是否計入等待成本時要說明假設。

備援程式是 Codex 製作的教學解答，不是你的實測成果。使用備援時請在紀錄中註明。

課後練習：行事曆匯出

將收藏議程匯出為 .ics。每場一個 VEVENT，包含穩定 UID、DTSTAMP、開始與結束時間、名稱及會議室。轉成 UTC 後使用 Z 結尾，正確跳脫文字並以 CRLF 分行。測試中文、逗號、分號、換行及沒有收藏的情境。延伸提示與參考實作見 extension-ics.md。
